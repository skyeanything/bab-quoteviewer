# BAB QuoteViewer

A local quote viewer and working WebSocket client for teams integrating an App backend with MT5 Bridge. The .NET process receives all symbols in one account group through **one upstream connection**. A browser page shows prices, freshness, connection count and successful JWT renewals.

QuoteViewer is a diagnostic client. It does not run MT5, load the Manager SDK or place trades. The browser connects only to the local viewer; JWTs remain in the receiving process.

Read the [market-data integration guide](docs/market-data-integration.md) for the complete authentication and subscription contract.

## Requirements

- .NET SDK 10 and Python 3.
- An authorized Bridge endpoint with **in-connection JWT renewal** support.
- A configured source ID, exact MT5 account-group name and authorized token provider.
- Node.js 22 or later only for the optional UI regression test.

All addresses, identities and groups shipped here are examples. Obtain deployment values privately from the Bridge operator.

## Start the viewer

1. Copy `config.example.json` to `config.json`.
2. Set `bridgeUrl` to the supplied WebSocket base URL, without `/v1/...`. Set `sourceId` and `group` to the authorized values.
3. Set `tokenCommand` to an executable and its argument list. This command runs once for connection setup and again before each renewal. It must write exactly one JSON object to stdout:

   ```json
   {"token":"<fresh-signed-jwt>","expiresAt":1800000120}
   ```

   `expiresAt` is the JWT `exp` as Unix UTC seconds. The timestamp above is illustrative. Return a freshly issued token each time. Put diagnostics on stderr, never tokens or signing keys. Commands run from the repository root, without a shell; do not use shell pipelines in the argument list.

4. Start the receiving process:

   ```sh
   python3 start.py
   ```

5. Open [the local viewer](http://localhost:8877). The default port is configurable through `httpPort`.

The viewer requests `{"all":true}`, keeps receiving quotes during authorization renewal and schedules the next renewal from the server's acknowledgment. A normal renewal does not clear prices or increment the connection count. A real disconnect retains cached prices with a stale status; a new connection must receive fresh data before marking those rows live again.

The UI displays deployment addresses and raw quote messages at runtime. Check screenshots and logs before sharing them.

## Example token issuer

Use the included issuer only when the Bridge operator has authorized this signing backend and registered the corresponding RSA public key. An arbitrary key generated by a consumer will not be trusted automatically. In a deployed App, keep signing in the trusted backend or obtain tokens from your existing authenticated token service.

```sh
dotnet build examples/TokenIssuer/TokenIssuer.csproj -c Release
```

Copy `examples/TokenIssuer/config.example.json` to `issuer.local.json` in the repository root. Set the agreed issuer, audience, key ID, stable caller ID, source and group. Set `privateKeyFile` to your protected private-key file. Relative key paths resolve against the issuer configuration file's directory. The sample defaults to 120-second tokens; use a shorter lifetime if the Bridge configuration requires one.

The default `tokenCommand` in `config.example.json` invokes this built issuer. No key, credential or real deployment configuration is included. `config.json`, `*.local.json`, private-key files and `secrets/` are ignored by Git.

## Verify the client

```sh
dotnet build QuoteViewer.csproj
dotnet run --project tests/Smoke/Smoke.csproj
node --test tests/ui.test.mjs
```

The smoke test uses a local protocol fixture and short test credentials. It verifies two renewal boundaries on one socket, rejection without extending authorization, and stale-cache preservation through a real socket disconnect. The UI test verifies renewal and reconnect display behavior. The fixture is not a JWT security validator or a substitute for testing a deployed Bridge.

For deployment acceptance, keep the viewer open through at least two token expiry boundaries. Confirm that successful renewals increase, connection count remains one, messages continue, and live symbols do not disappear at renewal. Idle or closed markets can legitimately become stale; an all-group subscription does not guarantee every symbol currently has a tick.

## Files

| File | Purpose |
| --- | --- |
| `QuoteFeed.cs` | Upstream connection, subscription, JWT renewal and quote cache |
| `Program.cs` | Local HTTP/SSE adapter; binds to localhost |
| `wwwroot/index.html` | Browser table, search, freshness and session status |
| `start.py` | Configuration-based launcher |
| `examples/TokenIssuer/` | RS256 issuer example for an authorized signing backend |
| `docs/market-data-integration.md` | Backend integration protocol and JWT rules |

The quote stream coalesces intermediate updates and does not replay all ticks missed during an outage. It is suitable for latest-price displays, not a complete tick archive.
